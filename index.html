Tom Mitchell's experience–task–performance definition

Tom Mitchell frames learning as improvement: a program learns from experience (E) when its measured performance (P) on a task (T) gets better. This is more useful than saying a system merely “uses data,” because every word can be made concrete and tested.

Learning is not memorizing. The real test is whether experience helps on fresh cases that were not used to adjust the model.

Represent

Linear algebra is geometry with coordinates

Picture: a vector is a location or directed move; a matrix is a rule that moves every vector consistently.

Build: each output coordinate is a dot product between one row of \(W\) and the input \(\mathbf{x}\). Large aligned weights amplify a feature; opposite signs suppress it.

ML bridge: \(W\mathbf{x}+\mathbf b\) mixes input evidence into learned features. Shape tells the story: \(W\in\mathbb R^{m\times d}\) turns \(d\) inputs into \(m\) outputs.

Measure change

Calculus asks “what would a tiny nudge do?”

Picture: zoom into a smooth curve until it looks straight. The slope of that local line is the derivative.

Build: \(f'(x)=\lim_{h\to0}[f(x+h)-f(x)]/h\). A gradient collects one such sensitivity for every input direction.

ML bridge: \(\partial L/\partial w_j\) predicts how loss changes after nudging weight \(w_j\). Its sign chooses direction; its magnitude measures sensitivity.

Improve

Optimization turns sensitivity into a move

Picture: on a foggy hillside you cannot see the valley, but the local slope still tells which way is downhill.

Build: \(\theta_{t+1}=\theta_t-\eta\nabla L(\theta_t)\). The minus sign reverses uphill; \(\eta\) decides how much of the proposed move to trust.

ML bridge: repeated mini-batch estimates trade exactness for fast, useful progress. Momentum averages recent directions so noisy steps do not zigzag as much.

Reason under uncertainty

Probability separates possibility from belief

Picture: a distribution spreads one unit of belief across competing outcomes. Evidence moves that belief; it does not create certainty from nowhere.

Build: Bayes' rule \(p(h\mid d)\propto p(d\mid h)p(h)\) combines prior plausibility with how expected the data is under each hypothesis.

ML bridge: calibration asks whether events predicted at 80% really happen about 80% of the time. Accuracy alone cannot answer that.

Scale up

Matrix calculus is careful bookkeeping

Picture: a computation graph is a network of local cause-and-effect statements. Backprop sends one “responsibility signal” backward through each edge.

Build: Jacobians record how every output responds to every input. Vector–Jacobian products compute the needed gradient without materializing a giant Jacobian.

ML bridge: transposes are not decoration: they reverse the direction of a linear map so output responsibility can be assigned back to inputs and weights.

Linear algebra: what the network is

Think of a matrix as a magic machine that bends space. Each layer takes a vector and transforms it.

Matrices are necessary for deep learning because every layer is a matrix multiply that bundles thousands of weights, so we can compute many neuron activations and whole batches in one fast step.

\[ \mathbf{h} = W\mathbf{x} + \mathbf{b} \] \[ \mathbf{a} = \mathrm{ReLU}(\mathbf{h}) \]

Imagine a grid of points being stretched and tilted. That is what \(W\) does.

  • Vectors are arrows (direction + length).
  • Matrices are transformations (stretch, rotate, shear).
  • Layers stack these transformations with a nonlinearity.

Calculus: how learning works

Derivatives tell us how fast things change. If the loss is a hill, the derivative tells the slope.

Let \(y = g(x)\) and \(L = f(y)\). A tiny nudge \(dx\) changes \(y\) by \(dy = g'(x)dx\), which changes the loss by \(dL = f'(y)dy\).

\[ y = g(x), \quad L = f(y) \] \[ \frac{dL}{dx} = \frac{dL}{dy} \cdot \frac{dy}{dx} = f'(g(x)) \cdot g'(x) \]

Backprop is the chain rule applied again and again through the whole network.

  • Local slope \(\times\) upstream slope = new slope.
  • Each layer multiplies by its derivative and passes the signal back.

Optimization: gradient descent and learning rate

Once we know the slope, we take a step downhill to reduce the loss.

For a linear layer \( \mathbf{z} = W\mathbf{x} + \mathbf{b} \) with softmax + cross-entropy, the error at the logits is \( \hat{\mathbf{y}} - \mathbf{y} \).

\[ W \leftarrow W - \eta (\hat{\mathbf{y}} - \mathbf{y}) \mathbf{x}^T, \quad \mathbf{b} \leftarrow \mathbf{b} - \eta (\hat{\mathbf{y}} - \mathbf{y}) \]
  • \(\eta\): learning rate (step size)
  • \(\hat{\mathbf{y}} - \mathbf{y}\): probability error signal from the loss
  • \(\mathbf{x}\): input features that scale the step
  • Too big → unstable or diverges
  • Too small → slow progress
Mini mission: choose a step size that reaches the valley without bouncing.

Probability + information theory

For classification, the network turns scores into probabilities and compares them to the truth.

\[ \mathbf{z} = W\mathbf{x} + \mathbf{b} \] \[ \hat{\mathbf{y}} = \mathrm{softmax}(\mathbf{z}), \quad \hat{y}_i = \frac{e^{z_i}}{\sum_k e^{z_k}} \] \[ L = -\sum_i y_i \log \hat{y}_i \]
  • Scores \(\mathbf{z}\): raw logits before normalization.
  • \(\hat{\mathbf{y}}\): softmax outputs probabilities that sum to 1.
  • \(\mathbf{y}\): the true label as a one-hot distribution.
  • Loss \(L\): cross-entropy penalizes low probability on the true class; minimizing \(L\) pushes \(\hat{\mathbf{y}}\) toward \(\mathbf{y}\).

Loss derivation: with \( \hat{\mathbf{y}} = \mathrm{softmax}(\mathbf{z}) \) and one-hot \( \mathbf{y} \), the log-softmax derivative gives a simple gradient.

\[ \frac{\partial L}{\partial z_j} = \sum_i y_i (\hat{y}_j - \delta_{ij}) = \hat{y}_j - y_j \]

Result: \( \nabla_{\mathbf{z}} L = \hat{\mathbf{y}} - \mathbf{y} \), the signal that drives backprop.

Matrix calculus: the speed path

To train fast, we compute gradients for a whole batch at once. Think of matrices as a neat way to stack many examples and do one big calculation.

  • \(X\): a batch of inputs (rows are examples).
  • \(W\): weights (columns are feature-to-output recipes).
  • \(Y\): outputs for the whole batch.
\[ Y = XW \] \[ \frac{\partial L}{\partial X} = \frac{\partial L}{\partial Y} W^T \] \[ \frac{\partial L}{\partial W} = X^T \frac{\partial L}{\partial Y} \]

Intuition: each gradient formula is "reverse flow" of the forward pass. We transpose the weight matrix to send signals back to the inputs, and we combine all examples with \(X^T\) to update the weights in one shot.

  1. Forward pass: multiply the batch \(X\) by weights \(W\) to get outputs \(Y\).
  2. Backprop to inputs: push gradients through \(W^T\) to get \( \partial L / \partial X \).
  3. Backprop to weights: combine \(X^T\) with \( \partial L / \partial Y \) to get \( \partial L / \partial W \).

Shapes are your superpower: if \(X\) is \(n \times d\) and \(W\) is \(d \times m\), then \(Y\) is \(n \times m\). The gradients match those same shapes.

\[ \det(A) = ad - bc \]

Determinant is the area scale factor; sign indicates a flip.

  • Small determinants signal near-singular matrices.
  • Precision matrices reweight directions in space.
  • Eigenvectors preserve direction under \(A\).

Derivations: covariance, precision, eigen

Determinant (2x2)

\[ A = \begin{bmatrix} a & b \\ c & d \end{bmatrix}, \quad \det(A)=ad-bc \]
  1. Expand by the first row: \(a\cdot d - b\cdot c\).
  2. \(|\det(A)|\) is area scale; sign means flip.
  3. \(\det(A)=0\) implies no inverse exists.

Inverse (2x2)

\[ A^{-1}=\frac{1}{\det(A)}\begin{bmatrix} d & -b \\ -c & a \end{bmatrix} \]
  1. Require \(\det(A)\neq 0\).
  2. Swap the diagonal, negate off-diagonals.
  3. Divide by \(\det(A)\) so \(AA^{-1}=I\).

Covariance matrix

\[ \mu=\frac{1}{n}\sum_{i=1}^n x_i,\quad X_c = X-\mathbf{1}\mu^T \] \[ \Sigma=\frac{1}{n-1}X_c^T X_c \]
  1. Center each feature: subtract the mean \(\mu\).
  2. Accumulate outer products: \(x_c x_c^T\).
  3. Average: \(\Sigma_{xy}=\frac{1}{n-1}\sum (x_i-\mu_x)(y_i-\mu_y)\).

Precision matrix

\[ \Lambda = \Sigma^{-1} = \frac{1}{\sigma_x^2 \sigma_y^2 - \sigma_{xy}^2} \begin{bmatrix} \sigma_y^2 & -\sigma_{xy} \\ -\sigma_{xy} & \sigma_x^2 \end{bmatrix} \]
  1. Compute \(\det(\Sigma)\).
  2. Apply the 2x2 inverse formula.
  3. In a Gaussian, \((x-\mu)^T\Lambda(x-\mu)\) is the Mahalanobis distance.

Eigenvalues & eigenvectors

\[ A\mathbf{v}=\lambda \mathbf{v},\quad \det(A-\lambda I)=0 \] \[ \lambda=\frac{\operatorname{tr}A \pm \sqrt{(\operatorname{tr}A)^2-4\det(A)}}{2} \]
  1. Solve the characteristic equation for \(\lambda\).
  2. Plug into \((A-\lambda I)\mathbf{v}=0\) to get \(\mathbf{v}\).
  3. For symmetric \(A\), eigenvectors are orthonormal axes.

Why negative log likelihood becomes the loss

Training chooses parameters that make the observed labels most probable. This is maximum likelihood estimation.

  1. Model the probability of the correct label. For each example \( (x_i, y_i) \), the model returns \( p_\theta(y_i \mid x_i) \).
  2. Likelihood of the dataset. Assuming samples are independent, \( L(\theta) = \prod_{i=1}^N p_\theta(y_i \mid x_i) \).
  3. Log-likelihood simplifies the product. The log is monotonic, so maximizing \(L\) matches maximizing \( \log L = \sum_i \log p_\theta(y_i \mid x_i) \), and it avoids numerical underflow.
  4. Negative log-likelihood is the minimization objective. We minimize \( \mathcal{L}(\theta) = -\log L(\theta) \). For one-hot classification, this is cross-entropy.
\[ \mathcal{L}(\theta) = -\frac{1}{N}\sum_{i=1}^N \log p_\theta(y_i \mid x_i) = -\frac{1}{N}\sum_{i=1}^N \sum_k y_{ik} \log \hat{y}_{ik} \]

Step 1: Multiply

\[ L = 0.9 \times 0.6 \times 0.2 = 0.108 \]

Step 2: Log-sum

\[ \begin{aligned} \log L &= \log 0.9 + \log 0.6 + \log 0.2 \\ &= -0.105 - 0.511 - 1.609 \\ &= -2.225 \end{aligned} \]

Step 3: Negate

\[ \mathcal{L} = -\log L = 2.225 \]

Low loss means the model assigns high probability to the true labels; overconfident mistakes are penalized most.

Hidden Markov Models & filters

What is a Hidden Markov Model?

A Hidden Markov Model (HMM) describes a system with hidden states that evolve over time and generate observable data.

  • Hidden states transition via a Markov process.
  • Observations are emitted based on the current hidden state.
  • The task is to infer hidden states from observations.
\[ P(X_t \mid X_{t-1}) \quad \text{and} \quad P(E_t \mid X_t) \]

Common uses: speech recognition, NLP, bioinformatics, and time-series analysis.

What filters do

Filters estimate hidden state as new, noisy observations arrive, updating beliefs step by step.

  • Continuous states and observations.
  • Linear dynamics and observation models.
  • Gaussian noise assumptions.

The Kalman filter provides an optimal recursive estimate under those conditions.

Used in radar tracking, navigation, and robotics for position/velocity estimates.

Activation Functions

Non-Linear Transformations

Activation functions add non-linearity to neural networks, enabling them to learn complex patterns:

Sigmoid: \( \sigma(x) = \frac{1}{1+e^{-x}} \)

Squashes values to (0, 1). Used for binary classification.

ReLU: \( f(x) = \max(0, x) \)

Most popular! Simple and effective. Returns x if positive, 0 otherwise.

Tanh: \( \tanh(x) = \frac{e^x - e^{-x}}{e^x + e^{-x}} \)

Squashes values to (-1, 1). Zero-centered version of sigmoid.

\[f(\mathbf{x}+\Delta\mathbf{x})\approx f(\mathbf{x})+\nabla f(\mathbf{x})^T\Delta\mathbf{x}.\]

2. Ask for the largest rise

With \(\lVert\Delta\mathbf{x}\rVert=\varepsilon\), Cauchy–Schwarz bounds the change by \(\varepsilon\lVert\nabla f\rVert\).

3. Align the nudge

The bound becomes equality when \(\Delta\mathbf{x}\) points with the gradient. Therefore \(-\nabla f\) is steepest descent.

What do the symbols mean?

Start with a circle of radius one. A signed angle θ selects one point on the circle. Drop that point onto the horizontal and vertical axes. The horizontal coordinate is called cosine; the vertical coordinate is called sine.

Rotation: the matrix is made from moved basis vectors

(cos α, sin α)(−sin α, cos α)α

What does it take to rotate every vector?

A linear transformation is completely determined by where it sends the two basis vectors. Rotating the horizontal unit vector by α gives (cos α, sin α). The vertical unit vector begins a quarter-turn ahead, so it lands at (−sin α, cos α). Those destination vectors become the matrix columns.

R(α) = [[cos α, −sin α], [sin α, cos α]]

Why the minus sign is necessary. The two columns must remain perpendicular, have length one, and keep their counterclockwise orientation. The vector (−sin α, cos α) is exactly the quarter-turn of (cos α, sin α).

Angle addition: two turns have one endpoint

first: Bthen: Asame endpoint: A + B

Why must the angle-addition formulas have their particular signs and products?

Rotate by B, then rotate the result by A. Physical rotations add, so this two-step motion is identical to one rotation by A+B. Therefore the matrices must be equal: R(A)R(B) = R(A+B).

sin(A+B) = sin A cos B + cos A sin Bcos(A+B) = cos A cos B − sin A sin B

Proof by comparing coordinates. Multiply the matrices and compare the first column. Its lower entry gives the sine formula; its upper entry gives the cosine formula. The formulas are forced by the fact that both motions reach the same point.

    What is Machine Learning?

    A model has learned only when experience produces measurable improvement on a defined task—not merely when it stores the training examples.

    The operational definition

    Specify (T), (E), and (P) before choosing an algorithm

    In Tom Mitchell's framework, a computer program learns when experience (E) improves performance (P) at task (T). The definition forces a vague goal—“make it intelligent”—into a claim that an experiment can confirm or reject.

    House-price example

    Task (T)Predict the sale price of a new house from its features.

    Experience (E)Past homes with size, location, age, and sale price.

    Performance (P)Lower mean absolute error on held-out future sales.

    From examples to a rule

    The learning loop, one idea at a time

    1. Represent the case. Features \(\mathbf x\) turn a house, image, or sentence into numbers a model can operate on.
    2. Make a guess. A parameterized function \(f_\theta(\mathbf x)\) produces prediction \(\hat y\). Parameters \(\theta\) are the adjustable parts.
    3. Measure the miss. A loss \(\mathcal L(\hat y,y)\) converts “how wrong?” into a number. The loss defines what improvement means during training.
    4. Assign responsibility. Optimization estimates which parameter changes would lower loss, then updates \(\theta\).
    5. Test the rule elsewhere. Validation and test data reveal whether the model learned a reusable pattern or memorized accidents in the training set.
    \[ \theta^* = \arg\min_\theta \frac{1}{n}\sum_{i=1}^{n}\mathcal L\big(f_\theta(\mathbf x_i),y_i\big) \]

    The equation says: among the allowed models, search for parameters whose predictions have the smallest average training penalty. It does not guarantee useful behavior on new data; data quality, evaluation design, regularization, and assumptions about the future provide that bridge.

    Machine Learning Algorithms

    Algorithms differ mainly in the shape of rule they can express and the assumptions they make about useful structure.

    Regression: draw a trend

    Choose a line or curve that keeps prediction residuals small. Regularization prefers a simpler trend unless extra complexity earns enough error reduction.

    Classification: divide a space

    Each feature is an axis. A classifier learns boundaries that place different labels in different regions, then reports a class or probability.

    Trees: ask useful questions

    Each split asks one yes/no question. Training chooses questions that make the child groups purer; a path from root to leaf becomes an explanation.

    Nearest neighbors: compare cases

    Nearby examples vote or average. “Nearby” depends entirely on the distance and feature scaling, so representation is part of the algorithm.

    Clustering: find prototypes

    Alternately assign points to the closest center and move each center to its assigned mean. The loop shrinks within-cluster distance.

    Ensembles: combine imperfect views

    Averaging weakly correlated errors can reduce variance. Bagging trains peers on resampled data; boosting trains each learner to repair earlier mistakes.

    Common algorithm families

    • Supervised: learn from labeled examples to predict or classify.
    • Unsupervised: discover structure without labels.
    • Probabilistic: express uncertainty with likelihoods and priors.
    • Ensembles: combine many models to reduce error.

    Formulas and derivations

    Short derivations that connect each algorithm to its core objective.

    Linear Regression

    \[ J(\mathbf{w}) = \frac{1}{n}\lVert X\mathbf{w} - \mathbf{y} \rVert^2 \]
    1. Take gradient: \( \nabla J = \frac{2}{n} X^T (X\mathbf{w} - \mathbf{y}) \).
    2. Set to zero: \( X^T X \mathbf{w} = X^T \mathbf{y} \).
    3. Solve for \( \mathbf{w} \) (normal equation) or use gradient descent.

    Logistic Regression

    \[ L = -\sum_i y_i \log \sigma(z_i) + (1-y_i)\log(1-\sigma(z_i)) \]
    1. Let \( z_i = \mathbf{w}^T \mathbf{x}_i + b \), \( p_i = \sigma(z_i) \).
    2. Derivative: \( \partial L / \partial z_i = p_i - y_i \).
    3. Gradient: \( \nabla_{\mathbf{w}} L = X^T(\mathbf{p} - \mathbf{y}) \).

    k-NN

    \[ \hat{y} = \text{mode}\{y_i : i \in \mathcal{N}_k(x)\} \]
    1. No training objective; store all labeled points.
    2. Compute distances \( d(x, x_i) \) to all points.
    3. Pick the k closest neighbors and vote (or average for regression).

    Decision Trees

    \[ \text{Gain} = H(\text{parent}) - \sum_k p_k H(\text{child}_k) \]
    1. Compute impurity (entropy or Gini) at the parent node.
    2. Evaluate candidate splits and compute weighted child impurity.
    3. Choose the split with the largest information gain.

    Random Forest

    \[ \hat{y} = \frac{1}{T} \sum_{t=1}^T h_t(x) \]
    1. Train many trees on bootstrapped samples with random feature subsets.
    2. Aggregate predictions by averaging or voting.
    3. Averaging reduces variance when trees are diverse.

    Support Vector Machine

    \[ \min_{\mathbf{w}} \; \frac{1}{2}\lVert \mathbf{w} \rVert^2 + C \sum_i \max(0, 1 - y_i \mathbf{w}^T \mathbf{x}_i) \]
    1. Maximize margin by minimizing \( \lVert \mathbf{w} \rVert^2 \).
    2. Hinge loss penalizes points inside the margin or misclassified.
    3. Only support vectors affect the optimal boundary.

    Naive Bayes

    \[ P(y \mid x) \propto P(y)\prod_i P(x_i \mid y) \]
    1. Start from Bayes: \( P(y \mid x) = P(x \mid y)P(y)/P(x) \).
    2. Assume conditional independence: \( P(x \mid y) = \prod_i P(x_i \mid y) \).
    3. Choose the class with the largest posterior.

    k-Means

    \[ \min_{\{\mu_k\}} \sum_i \lVert x_i - \mu_{c_i} \rVert^2 \]
    1. Assign each point to the nearest centroid.
    2. Update centroids by setting \( \partial J / \partial \mu_k = 0 \Rightarrow \mu_k = \text{mean} \).
    3. Repeat until assignments stabilize.

    PCA

    \[ \max_{\lVert \mathbf{w} \rVert = 1} \mathbf{w}^T \Sigma \mathbf{w} \]
    1. Use Lagrange multiplier: \( \Sigma \mathbf{w} = \lambda \mathbf{w} \).
    2. The top eigenvector gives the max-variance direction.
    3. Project data onto the leading eigenvectors.

        Lesson 1 · How models work

        A decision tree turns questions into regions of similar outcomes

        A supervised model learns a function \(f:X\rightarrow y\) from examples whose answers are already known. A regression tree learns a sequence of feature thresholds. Each split sends a row left or right; the reached leaf predicts the mean target of its training rows.

        Trace one prediction

        1. Features are evidence. A house becomes a row such as [living_area, quality, age]. Feature order and units are part of the model’s input contract.
        2. Training chooses questions. The tree tests candidate feature thresholds and prefers the split that most reduces within-leaf squared error.
        3. A leaf stores an estimate. For squared-error regression, that estimate is the mean sale price of the training rows in the leaf.
        4. Inference only follows rules. No parameters change during predict; a new row traverses the learned tree.
        \[\operatorname{SSE}(R)=\sum_{i\in R}(y_i-\bar y_R)^2,\qquad \hat y(x)=\bar y_{\operatorname{leaf}(x)}\]

        Reasoning check: a tree does not “understand” houses. It partitions the measured feature space and transfers averages from nearby training regions.

        The estimator API

        DecisionTreeRegressor(max_leaf_nodes=…)

        Constructs an unfitted estimator and stores hyperparameters. max_leaf_nodes limits structural capacity.

        model.fit(X, y)

        Learns split features, thresholds, and leaf values from aligned feature rows \(X\) and targets \(y\). Returns the fitted estimator.

        model.predict(X_new)

        Returns one numeric estimate per new row. The input must preserve the feature schema used during fitting.

        model.tree_

        Exposes the fitted low-level tree: node features, thresholds, children, sample counts, and values.

        Lesson 4 · Model validation

        Measure the model on rows it could not memorize

        Training error answers “how well did the model fit its examples?” Validation error asks the deployment question: “how accurately does the fitted procedure predict unseen rows from the same process?” Keep validation targets completely outside fit.

        The holdout protocol

        1. Split aligned \(X,y\) rows into training and validation subsets.
        2. Fit the estimator using only train_X, train_y.
        3. Predict val_X; compare predictions with untouched val_y.
        4. Use the metric to compare modeling choices, then preserve a final test set for the last unbiased estimate when stakes justify it.
        \[\operatorname{MAE}(y,\hat y)=\frac{1}{n}\sum_{i=1}^{n}|y_i-\hat y_i|\]

        MAE has the target’s units. An MAE of $18,000 means the prediction misses by $18,000 on average in absolute value; it does not reveal whether a few catastrophic errors dominate.

        Leakage rule: fit preprocessing, feature selection, and models on training data only. “Looking” at validation labels repeatedly also turns the validation set into training feedback.

        Validation API contract

        train_test_split(X, y, test_size=.2, random_state=1)

        Shuffles aligned inputs and returns train_X, val_X, train_y, val_y. The seed makes the split repeatable.

        model.fit(train_X, train_y)

        Mutates the estimator by learning from the training partition. Validation rows must not enter this call.

        model.predict(val_X)

        Runs inference on held-out features. Output length equals len(val_X).

        mean_absolute_error(val_y, val_predictions)

        Averages absolute residuals. Lower is better; zero is perfect.

        Lesson 5 · Underfitting and overfitting

        Model capacity must be large enough to learn signal and small enough to ignore accidents

        A shallow tree groups unlike cases together and underfits. A huge tree can isolate individual training rows and overfit. Select capacity using validation performance—not training accuracy and not visual complexity alone.

        Read the two error curves together

        • Too few leaves: training and validation error are both high. The representation is too coarse.
        • Useful capacity: validation error reaches its minimum. Added structure is capturing repeatable signal.
        • Too many leaves: training error keeps falling while validation error rises. The gap is evidence of memorizing sample-specific noise.
        def get_mae(max_leaf_nodes, train_X, val_X, train_y, val_y):
    model = DecisionTreeRegressor(
        max_leaf_nodes=max_leaf_nodes,
        random_state=1

    model.fit(train_X, train_y)
    return mean_absolute_error(val_y, model.predict(val_X))

        Lesson 6 · Random forests

        Average diverse trees to reduce unstable mistakes

        A random forest trains many decision trees on bootstrapped rows while considering random feature subsets at splits. Their individual errors are imperfectly correlated, so averaging usually reduces variance without requiring you to find one perfect tree.

        \[\hat y_{\text{forest}}(x)=\frac{1}{T}\sum_{t=1}^{T}\hat y_t(x),\qquad \operatorname{Var}(\bar y)\downarrow\ \text{when tree errors differ}\]
        1. Bootstrap rows: each tree receives a same-sized sample drawn with replacement, so some rows repeat and others are left out.
        2. Randomize features: each split considers only a subset, preventing one dominant feature from making all trees identical.
        3. Grow independent structures: the resampled evidence produces different thresholds and leaves.
        4. Aggregate: regressors average; classifiers vote or average class probabilities.

        Trade-off: more trees generally stabilize the estimate but cost memory and computation. Forests still inherit data leakage, invalid validation, and feature-timing problems.

          Why weights?

          They encode relevance and direction

          A positive weight makes the output rise when its feature rises. A negative weight makes it fall. A near-zero weight makes that feature almost irrelevant. Training discovers these values from examples.

          Why a bias?

          It moves the threshold

          Without \(b\), every linear boundary must pass through the origin. Bias lets the neuron prefer “on” or “off” before seeing evidence and place its decision boundary where the data requires.

          Why an activation?

          It lets layers bend

          Stacking linear maps alone collapses to one linear map: \(W_2(W_1x)=W'x\). A nonlinear \(\phi\) breaks that collapse, letting many simple boundaries combine into curved, disconnected regions.

          Why layers?

          They compose reusable features

          Early image layers can respond to oriented edges; later layers combine those responses into textures, parts, and task-specific patterns. Depth means composition, not automatic understanding.

          Backpropagation in plain language

          Suppose the final loss changes by \(dL\). The output layer knows how its output changed with its input; the previous layer knows the same local relationship for its own operation. The chain rule multiplies those local sensitivities, so each parameter receives \(\partial L/\partial w\): the predicted loss change per tiny change in that weight. Backprop is the efficient reuse of these backward signals, not a separate learning objective.

          \[ \frac{\partial L}{\partial w} =\frac{\partial L}{\partial a} \frac{\partial a}{\partial z} \frac{\partial z}{\partial w} \]

            What is a Transformer?

            Transformer is a neural network architecture that has fundamentally changed the approach to artificial intelligence. It was introduced in the 2017 paper "Attention is All You Need" and now powers models like OpenAI GPT, Meta Llama, and Google Gemini.

            Transformers are not limited to text. They also drive audio generation, image recognition, protein structure prediction, and game playing, showing how broadly the architecture applies across domains.

            Text-generative Transformers operate on next-token prediction: given a prompt, the model estimates the most probable next token. The core innovation is self-attention, which lets all tokens communicate and capture long-range dependencies.

            Transformer Explainer is powered by GPT-2 (small) with 124 million parameters. While it is not the largest model, its components match the structure of more recent systems.

            Transformer architecture

            Every text-generative Transformer consists of three components:

            • Embedding: tokens become vectors and receive positional signals.
            • Transformer block: multi-head attention routes context; an MLP refines each token.
            • Output probabilities: logits are turned into a probability distribution for the next token.

            Embedding pipeline

            Suppose the prompt is: "Data visualization empowers users to". Embedding converts this text into a numerical representation in four steps:

            1. Tokenization: split into word or subword tokens.
            2. Token embedding: map tokens to a vector space.
            3. Positional encoding: add position information.
            4. Final embedding: sum token and positional vectors.

            Figure 1. Expanding the embedding view: tokenization, token embedding, positional encoding, and final embedding.

            GPT-2 (small) uses 768-dimensional embeddings and a vocabulary of 50,257 tokens. The embedding matrix has shape (50,257, 768) with about 39 million parameters.

            Transformer block

            The block combines multi-head self-attention and an MLP. GPT-2 (small) stacks 12 blocks, allowing token representations to evolve into higher-level meanings over depth.

            Multi-head attention captures context across tokens. The MLP processes each token independently to refine its representation.

            Multi-head self-attention

            Each token is transformed into Query (Q), Key (K), and Value (V) vectors:

            \[ QKV_{ij} = \left( \sum_{d=1}^{768} \text{Embedding}_{i,d} \cdot \text{Weights}_{d,j} \right) + \text{Bias}_j \]

            Query is like the search text, Key is the result title, and Value is the page content. This analogy helps explain why attention scores route information from relevant tokens.

            Figure 2. Computing Q, K, and V from the embedding.

            • Split into heads: GPT-2 uses 12 attention heads.
            • Masked attention: prevents peeking at future tokens.
            • Concat + projection: heads are merged for the next stage.

            Scaling and masking set future positions to negative infinity so each token predicts without looking ahead.

            Figure 3. Masked self-attention: dot product, scale + mask, softmax + dropout.

            MLP: multi-layer perceptron

            The MLP expands each token from 768 to 3072 dimensions with a GELU activation, then compresses back to 768. This enriches the representation independently per token.

            Figure 4. The MLP expands then compresses each token representation.

            Output probabilities and sampling

            The final linear layer maps to 50,257 logits, one for each token in the vocabulary. Softmax turns logits into probabilities for the next token.

            Figure 5. Each token receives a probability from the output logits.

            Temperature controls sharpness: T=1 keeps logits unchanged, T<1 makes outputs more deterministic, and T>1 increases randomness.

            Temperature

            Lower values make outputs more deterministic; higher values add creativity.

            Top-k

            Restrict sampling to the top k highest-probability tokens.

            Top-p

            Sample from the smallest set whose cumulative probability exceeds p.

            Auxiliary architectural features

            Layer normalization stabilizes training and is applied twice per block. Dropout regularizes by randomly deactivating units during training and is disabled during inference. Residual connections add skip paths twice per block, helping gradients flow and preventing vanishing gradients.

            Depth 1

            Transformer fundamentals

            Mechanics and intuition.

            Tokens turn into Q/K/V, attention mixes them, FFN refines, residual + norm stabilize.

            The big picture

            Transformers model sequences by letting every token attend to every other token in one step, so computation is parallel instead of strictly sequential.

            Encoder-decoder stacks build a memory from the input, while decoder-only stacks generate the next token with a causal mask.

            Scaled dot-product attention

            Queries and keys produce similarity scores, softmax turns scores into weights, and values are mixed by a weighted sum.

            Scaling by sqrt(d) keeps logits in a stable range so softmax does not saturate too early.

            Multi-head + residuals + layer norm

            Each head attends in its own subspace, the heads are concatenated, and a projection mixes them back together.

            Residual paths keep the original signal available, while layer norm stabilizes scale across the block.

            Positional encoding

            Attention is permutation-invariant, so we add position signals to token embeddings before attention.

            Sinusoidal encodings give each position a unique mix of frequencies; learned or relative schemes encode distance directly.

            Depth 2

            Transformer into an LLM

            Training objectives and variants.

            Decoder-only uses causal masks for next-token prediction; encoder-only sees both directions with masked tokens.

            Decoder-only transformers (GPT-style)

            A causal mask blocks attention to future tokens, so each position can only use past context.

            Training uses teacher forcing: the model sees true previous tokens while learning to predict the next one.

            Encoder-only transformers (BERT-style)

            Masked language modeling hides tokens and uses both left and right context to reconstruct them.

            The result is a strong bidirectional representation that transfers well to classification and retrieval tasks.

            Training + inference basics

            Logits become probabilities via softmax, then decoding picks the next token.

            Greedy decoding is stable, while temperature and top-p sampling trade determinism for diversity.

            Depth 3

            Reasoning with transformers

            Prompting and tool-use strategies.

            CoT adds intermediate steps, self-consistency samples many paths, ReAct loops the model with tools.

            Chain-of-Thought (CoT)

            CoT encourages explicit intermediate steps, which can improve multi-step reasoning tasks.

            Use it when the reasoning path matters, but keep in mind verbosity does not guarantee correctness.

            Self-consistency

            Self-consistency samples multiple reasoning paths and aggregates the final answers.

            Majority voting reduces variance and often improves accuracy on reasoning benchmarks.

            ReAct (reason + act)

            ReAct alternates reasoning steps with tool calls, grounding answers in external data.

            The loop keeps the model honest by injecting retrieved facts before the final response.

            1. 1
              How does a network learn representations?

              Begin with backpropagation, distributed representations, and convolutional features. Read CS231n alongside AlexNet, then trace the tensor shapes through one small classifier.

              Build: convolution → activation → pooling → classifier.
            2. 2
              How can information survive through time?

              Study character RNNs, LSTMs, recurrent regularization, and Deep Speech 2. Compare a plain recurrent update with gated memory.

              Build: one character-level next-token predictor.
            3. 3
              How does a model select and store information?

              Connect Pointer Networks, Neural Turing Machines, relational networks, and the Annotated Transformer. The common problem is content-dependent routing.

              Build: attention scores, softmax weights, weighted value sum.
            4. 4
              Why do compression and generalization meet?

              Use minimum description length, weight description length, Kolmogorov complexity, and generative modeling to ask which regularities are worth encoding.

              Build: compare validation loss with a simple complexity penalty.
            5. 5
              What changes when models scale?

              Finish with scaling laws and the limits of the evidence. Separate an observed power law from a causal explanation or a claim about intelligence.

              Build: fit a log–log line and state what it predicts—and what it cannot.

            Use the same six questions for every paper

            1. Problem: what failure or limitation motivated the work?
            2. Prerequisite: which earlier idea must be understood first?
            3. Mechanism: what computation or training rule changed?
            4. Shape: what enters and leaves each important operation?
            5. Evidence: which experiment supports the central claim?
            6. Boundary: what remains untested, expensive, or fragile?

              Exercise 2.1 · 20 minutes

              Write the estimand before the prompt

              1. Choose a decision: enable a feature, prescribe a treatment, change a price, or issue an alert.
              2. Write one association question, one intervention question, and one unit-level counterfactual.
              3. Draw a directed graph with exposure, outcome, at least one cause of each, and any mediator.

              Self-check rubric

              A strong answer names the population, action, comparison, outcome, and horizon; separates prediction from intervention; and treats the graph as an assumption to criticize, not a fact inferred automatically from correlations.

              Reinforcement Learning Fundamentals

              Agents learn by interacting with an environment, collecting rewards, and improving a policy.

              Reinforcement learning (RL) is a learning framework where an agent chooses actions in a state, receives rewards, and updates its policy to maximize long-term return.

              \[ \text{Goal: } \max_\pi \; \mathbb{E}_\pi \left[\sum_{t=0}^{\infty} \gamma^t r_t \right] \]

              Core concepts

              • Agent & environment: the learner and the world it interacts with.
              • Episode / trajectory: a sequence of states, actions, and rewards.
              • Reward vs return: immediate feedback \(r_t\) vs discounted sum \(G_t\).
              • Discount \(\gamma\): weighs future rewards.
              • Policy \( \pi(a|s) \): behavior rule.
              • Value \( V^\pi(s) \), Action-value \( Q^\pi(s,a) \).
              • Optimal \( V^*, Q^* \): best achievable values.

              Minimal environment interface

              reset(seed?) -> observation/state
step(action) -> { nextState, reward, done, info }
actions(state) -> action list
// render helpers stay separate from logic

              reset(seed?) starts a new episode and returns the initial state (optionally deterministic with a seed).

              step(action) applies an action and returns the transition tuple: next state, reward, terminal flag, and any extra info.

              actions(state) exposes valid actions so the agent can plan or explore safely.

              Render helpers stay separate so learning logic is deterministic and testable.

              \[ V^\pi(s) = \mathbb{E}_\pi\left[\sum_{t=0}^{\infty} \gamma^t r_{t} \mid s_0 = s \right] \] \[ Q^\pi(s,a) = \mathbb{E}_\pi\left[\sum_{t=0}^{\infty} \gamma^t r_{t} \mid s_0 = s, a_0 = a \right] \]

              Reinforcement Learning: a gentle mathematical walkthrough

              RL formalizes learning by experience: act, observe, update, repeat.

              1. Interaction over time

              At each step the agent is in a state \(s\), takes an action \(a\), receives a reward \(r\), and lands in a new state \(s'\).

              \[ s_0 \rightarrow a_0 \rightarrow r_1 \rightarrow s_1 \rightarrow a_1 \rightarrow r_2 \rightarrow s_2 \rightarrow \cdots \]

              This sequence is a trajectory (episode).

              2. Rewards vs return

              Rewards are immediate feedback. Returns add up future rewards with discounting.

              \[ G_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \cdots \]
              • \(\gamma = 0\): only care about now.
              • \(\gamma \approx 1\): care about long-term outcomes.

              3. Policy

              A policy tells the agent how to act:

              \[ \pi(a \mid s) \]
              • Deterministic: always take the same action.
              • Stochastic: choose actions by probability.

              4. Value functions

              Value functions measure how good states or actions are under a policy.

              \[ V^\pi(s) = \mathbb{E}_\pi\left[\sum_{t=0}^{\infty} \gamma^t r_t \mid s_0=s \right] \] \[ Q^\pi(s,a) = \mathbb{E}_\pi\left[\sum_{t=0}^{\infty} \gamma^t r_t \mid s_0=s, a_0=a \right] \]

              V evaluates a state; Q evaluates a decision.

              5. Bellman equations

              Value is defined recursively: immediate reward plus discounted value of the next state.

              \[ V^\pi(s) = \sum_a \pi(a \mid s) \sum_{s'} P(s' \mid s,a)\left[R(s,a,s') + \gamma V^\pi(s')\right] \] \[ V^*(s) = \max_a \sum_{s'} P(s' \mid s,a)\left[R(s,a,s') + \gamma V^*(s')\right] \]

              6. Dynamic programming (model known)

              If transitions and rewards are known, compute values directly.

              \[ V_{k+1}(s) = \max_a \sum_{s'} P(s' \mid s,a)\left[R + \gamma V_k(s')\right] \]

              Policy iteration alternates evaluation and greedy improvement.

              7. Monte Carlo methods

              Learn from complete episodes when the model is unknown.

              • Generate an episode and compute the return.
              • Update the first visit of each state (or state-action).
              • Unbiased but high variance; must wait for episode end.

              8. Temporal Difference (TD)

              Update values online using one-step bootstrapping.

              \[ V(s) \leftarrow V(s) + \alpha \left[r + \gamma V(s') - V(s)\right] \] \[ \delta = r + \gamma V(s') - V(s) \]

              \(\delta\) is the TD error: how wrong the prediction was.

              9. Learning control

              Learn the best actions, not just values.

              \[ Q(s,a) \leftarrow Q(s,a) + \alpha\left[r + \gamma Q(s',a') - Q(s,a)\right] \] \[ Q(s,a) \leftarrow Q(s,a) + \alpha\left[r + \gamma \max_{a'} Q(s',a') - Q(s,a)\right] \]

              SARSA uses the next action taken; Q-learning uses the best possible next action.

              10. Why deep RL exists

              Tables do not scale to high-dimensional states or continuous actions.

              • Approximate \(Q(s,a)\) or \(\pi(a \mid s)\) with neural networks.
              • Use experience replay to break correlation.
              • Use target networks to stabilize learning.
              • Optimize parameters with gradient descent.

                Common confusion

                State is a sufficient summary, not merely a screenshot

                The Markov property says the conditional distribution of the next state and reward depends on the present state and action, not on an omitted history. If the observation hides relevant history, the problem is partially observable and memory may be necessary.

                \[P(S_{t+1},R_{t+1}\mid S_t,A_t,S_{t-1},\ldots)=P(S_{t+1},R_{t+1}\mid S_t,A_t)\]

                Expectation is essential

                A value is not the reward from one rollout. It is the probability-weighted average return over environment randomness and the policy’s future actions. Sampling produces noisy estimates of that expectation.

                \[Q^\pi(s,a)=\mathbb{E}_\pi[G_t\mid S_t=s,A_t=a]\]

                Bootstrapping trades variance for bias

                Monte Carlo waits for the real return and is unbiased under on-policy sampling but noisy. TD replaces the unseen tail with a current estimate, reducing variance while introducing temporary bias.

                \[\delta_t=R_{t+1}+\gamma V(S_{t+1})-V(S_t)\]

                On-policy and off-policy answer different questions

                On-policy methods evaluate or improve the behavior that generated the data. Off-policy methods can learn about a target policy from another behavior policy, enabling replay and reuse but making distribution mismatch a central stability problem.

                Multi-Armed Bandits

                Explore exploration strategies and track regret as the agent learns.

                Algorithms

                • \(\varepsilon\)-greedy with optional decay.
                • UCB1 balances optimism and uncertainty.
                • Thompson Sampling for Bernoulli rewards.

                What is a multi-armed bandit? An agent repeatedly chooses among \(K\) actions (arms) with unknown reward distributions. The goal is to maximize total reward by balancing exploration (learn the arms) and exploitation (use the best-known arm).

                \(\varepsilon\)-greedy

                1. Initialize action-value estimates and counts.
                2. At each step, explore with probability \(\varepsilon\); otherwise exploit the best estimate.
                3. Pull the chosen arm and observe the reward.
                4. Update that arm’s estimate with an incremental mean.
                5. Optionally decay \(\varepsilon\) to reduce exploration over time.

                UCB1

                1. Initialize estimates and counts; try each arm at least once.
                2. Compute the UCB score: \( \hat{\mu}_a + c \sqrt{\log t / n_a} \).
                3. Select the arm with the highest UCB score.
                4. Observe the reward and update the estimate and count.
                5. Repeat to balance mean reward and uncertainty.

                Thompson Sampling (Bernoulli)

                1. Initialize Beta priors \(\alpha, \beta\) for each arm.
                2. Sample a success probability from each arm’s Beta distribution.
                3. Choose the arm with the highest sampled probability.
                4. Observe reward (success/failure) and update \(\alpha, \beta\).
                5. Repeat to naturally balance exploration and exploitation.

                Monte Carlo Methods

                Estimate values from complete episode returns.

                Algorithms

                • First-visit MC prediction for \(V^\pi\).
                • On-policy MC control with \(\varepsilon\)-soft policies.

                Deep dive: Monte Carlo methods. MC methods wait until an episode ends, then use the realized return to update value estimates. They are unbiased but can have high variance, so averaging many episodes stabilizes learning.

                First-visit MC prediction

                1. Generate a full episode using policy \(\pi\).
                2. For each state, find the first time it appears in the episode.
                3. Compute the return \(G_t\) from that first visit to the end.
                4. Update \(V(s)\) with the average of observed returns.
                5. Repeat with many episodes to reduce variance.

                On-policy MC control (\(\varepsilon\)-soft)

                1. Initialize \(Q(s,a)\) and a soft policy.
                2. Generate an episode following the current policy.
                3. Compute returns for each state-action first visit.
                4. Update \(Q(s,a)\) with averaged returns.
                5. Improve the policy to be \(\varepsilon\)-greedy w.r.t. \(Q\).

                Model-Free Control

                Learn optimal policies directly from experience.

                Algorithms

                • SARSA: on-policy TD control.
                • Q-learning: off-policy TD control.
                • Expected SARSA: expectation over policy.

                SARSA

                1. Initialize \(Q(s,a)\) and choose a behavior policy.
                2. Take action \(a\), observe \(r, s'\), and pick next action \(a'\) from the same policy.
                3. Update \( Q(s,a) \leftarrow Q(s,a) + \alpha [r + \gamma Q(s',a') - Q(s,a)] \).
                4. Set \(s \leftarrow s'\), \(a \leftarrow a'\) and repeat.

                Q-learning

                1. Initialize \(Q(s,a)\) and choose a behavior policy (e.g., \(\varepsilon\)-greedy).
                2. Take action \(a\), observe \(r, s'\).
                3. Update \( Q(s,a) \leftarrow Q(s,a) + \alpha [r + \gamma \max_{a'} Q(s',a') - Q(s,a)] \).
                4. Repeat until Q-values converge to \(Q^*\).

                Expected SARSA

                1. Initialize \(Q(s,a)\) and a stochastic policy.
                2. Observe \(r, s'\) after taking action \(a\).
                3. Compute expected next value \( \sum_{a'} \pi(a'|s') Q(s',a') \).
                4. Update \( Q(s,a) \leftarrow Q(s,a) + \alpha [r + \gamma \mathbb{E}_{a'}Q(s',a') - Q(s,a)] \).

                Deep RL Concepts

                When state spaces grow, deep networks approximate value functions or policies.

                Core ideas

                • Policy gradients optimize expected return directly.
                • Replay buffers stabilize off-policy learning.
                • Target networks reduce moving-target instability.

                Policy gradient (REINFORCE-style)

                1. Collect trajectories by sampling from \(\pi_\theta(a|s)\).
                2. Compute returns or advantages for each action.
                3. Estimate the gradient \( \nabla_\theta \log \pi_\theta(a|s) \hat{A} \).
                4. Update parameters \( \theta \leftarrow \theta + \alpha \nabla_\theta J(\theta) \).
                5. Repeat with variance reduction (baseline) for stability.

                Deep Q-learning (conceptual)

                1. Collect transitions into a replay buffer.
                2. Sample mini-batches uniformly from the buffer.
                3. Compute target \( r + \gamma \max_{a'} Q_{\text{target}}(s',a') \).
                4. Minimize the TD loss between \(Q_\theta\) and targets.
                5. Periodically sync the target network.
                \[ \nabla_\theta J(\theta) = \mathbb{E}_\pi[\nabla_\theta \log \pi_\theta(a|s) \, \hat{A}(s,a)] \]

                Deep RL diagnostic loop

                1. Collect experience into a replay buffer.
                2. Sample mini-batches for stable updates.
                3. Sync target networks periodically.
                4. Track reward curves and policy entropy.

                Policy gradient intuition

                Increase the probability of actions that led to higher return and decrease others.

                \[ \theta \leftarrow \theta + \alpha \nabla_\theta \log \pi_\theta(a|s) \, \hat{A} \]
                Value based · off-policy

                DQN

                Question: which discrete action has the greatest predicted return?

                \[y=r+\gamma(1-d)\max_{a'}Q_{\bar\theta}(s',a')\qquad L=(Q_\theta(s,a)-y)^2\]
                1. A replay buffer breaks short-range temporal correlation and reuses experience.
                2. A slowly updated target network holds the bootstrap target approximately fixed.
                3. The online network regresses its chosen-action estimate toward that target.

                Watch for: overestimated values, sparse-reward exploration, sensitivity to reward scale, and divergence when approximation, bootstrapping, and off-policy data interact.

                Actor–critic · on-policy

                PPO

                Question: how can a policy improve without one update moving it destructively far?

                \[L^{clip}=\mathbb E[\min(r_t(\theta)\hat A_t,\operatorname{clip}(r_t,1-\epsilon,1+\epsilon)\hat A_t)]\]
                1. The critic estimates value; advantages say whether sampled actions were better than expected.
                2. The probability ratio measures how much the new policy changes each sampled action.
                3. Clipping removes the incentive for excessively large probability changes.

                Watch for: the clipped objective is a heuristic, collected data becomes stale after updates, and implementation details strongly affect results.

                Actor–critic · off-policy

                Soft Actor-Critic

                Question: can continuous control reuse experience while maintaining broad, robust exploration?

                \[J(\pi)=\mathbb E\!\left[\sum_t\gamma^t(R_t+\alpha\mathcal H(\pi(\cdot\mid S_t)))\right]\]
                1. Twin critics reduce optimistic value errors.
                2. A stochastic actor chooses actions that trade expected value against entropy.
                3. Replay enables multiple updates per interaction; target critics stabilize bootstrapping.

                Watch for: entropy temperature, action scaling, critic extrapolation, and learning from a replay distribution unlike the current policy.

                03PyTorch 2.13 · tensors to production execution

                Build a differentiable program with explicit state

                A PyTorch model is ordinary Python whose tensor operations are recorded when gradients are enabled. Correctness depends on four simultaneous contracts: shape, dtype, device, and autograd history.

                Manim visual model

                Forward values create a graph; backward applies local derivatives in reverse

                Leaf tensors accumulate gradients. Non-leaf tensors remember the operation that created them. A training step must clear old gradients, run a fresh forward graph, call backward once per intended objective, and update without recording the optimizer itself.

                1

                Tensor contract

                Create with torch.tensor or factory functions; inspect shape, dtype, device, layout, and stride(). Use as_tensor/from_numpy when sharing is intended and clone when independence is intended.

                2

                Transform contract

                Index, broadcast, reduce, reshape, transpose, concatenate, and multiply with the same axis reasoning learned in NumPy. After a transpose, reshape may copy; use contiguous() only when an operator needs that layout.

                3

                Autograd contract

                Set requires_grad=True on floating or complex leaves. loss.backward() accumulates into .grad; detach() breaks history; no_grad and inference_mode disable recording for distinct use cases.

                4

                Module contract

                Subclass nn.Module, create child modules in __init__, define tensor computation in forward, and call the instance—not forward directly. Registered parameters and buffers move and serialize together.

                5

                Data contract

                A Dataset defines samples; a DataLoader batches, shuffles, and loads them. A transform changes one sample; collate_fn assembles a batch. Split before fitting data-dependent transforms.

                6

                Optimization contract

                Choose raw logits and a compatible loss, call zero_grad, forward, loss, backward, then step. Schedulers change the optimizer’s learning rate; AMP changes operation precision; gradient clipping bounds the update signal.

                7

                State contract

                state_dict contains registered model state. A resumable checkpoint also needs optimizer, scheduler/scaler, step, architecture, preprocessing, and data identity. Load untrusted artifacts defensively.

                8

                Execution contract

                model.eval() changes module behavior; inference_mode() changes autograd bookkeeping. Measure eager first, then evaluate torch.compile, export, quantization, distributed execution, and profiler evidence.

                PyTorch is an eager tensor runtime with automatic differentiation, a composable neural-network library, training utilities, compiler paths, and a broad ecosystem. The same Python objects move through the entire loop: data becomes tensors, modules transform tensors, autograd records the executed graph, optimizers update parameters, and inference reuses the forward computation without gradient bookkeeping.

                Tensor = data + metadata

                A tensor owns or views storage and describes it with a shape, strides, dtype, layout, and device. Shape errors are interface errors; dtype and device errors are execution errors.

                Autograd records what ran

                Operations on tensors requiring gradients create a directed acyclic graph. Each training iteration builds a fresh graph, so ordinary Python branches and loops can change the computation.

                Modules organize state

                nn.Module registers nested submodules, parameters, and buffers. state_dict(), to(device), train(), and eval() work across that tree.

                Loss creates one objective

                A scalar loss measures the prediction error. loss.backward() accumulates gradients into leaf parameters; it does not update weights.

                The optimizer owns the update rule

                step() reads parameter gradients and its own state—such as momentum or second moments—to update values. zero_grad() clears accumulated gradients.

                Inference is a distinct mode

                model.eval() changes stateful layer behavior; torch.inference_mode() disables autograd overhead. Production also considers batching, compilation, export, precision, and serving.

                import torch
from torch import nn
from torch.nn import functional as F

class CausalSelfAttention(nn.Module):
    def __init__(self, width, heads, dropout=0.0):
        super().__init__()
        assert width % heads == 0
        self.heads = heads
        self.dropout = dropout
        self.qkv = nn.Linear(width, 3 * width, bias=False)
        self.out = nn.Linear(width, width, bias=False)

    def forward(self, x):
        batch, time, width = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        shape = (batch, time, self.heads, width // self.heads)
        q, k, v = (z.view(shape).transpose(1, 2) for z in (q, k, v))
        y = F.scaled_dot_product_attention(
            q, k, v,
            dropout_p=self.dropout if self.training else 0.0,
            is_causal=True,
        )
        y = y.transpose(1, 2).contiguous().view(batch, time, width)
        return self.out(y)

class Block(nn.Module):
    def __init__(self, width, heads, dropout=0.0):
        super().__init__()
        self.ln1 = nn.LayerNorm(width)
        self.attn = CausalSelfAttention(width, heads, dropout)
        self.ln2 = nn.LayerNorm(width)
        self.mlp = nn.Sequential(
            nn.Linear(width, 4 * width), nn.GELU(),
            nn.Linear(4 * width, width), nn.Dropout(dropout),
        )

    def forward(self, x):
        x = x + self.attn(self.ln1(x))
        return x + self.mlp(self.ln2(x))

        _, time = token_ids.shape
        pos = torch.arange(time, device=token_ids.device)
        x = self.token(token_ids) + self.position(pos)
        logits = self.lm_head(self.norm(self.blocks(x)))
        loss = None if targets is None else F.cross_entropy(
            logits.flatten(0, 1), targets.flatten()
        )
        return logits, loss

    @torch.inference_mode()
    def generate(self, token_ids, new_tokens, temperature=0.8, top_k=40):
        self.eval()
        for _ in range(new_tokens):
            logits, _ = self(token_ids[:, -self.context:])
            logits = logits[:, -1] / max(temperature, 1e-5)
            k = min(top_k, logits.shape[-1])
            cutoff = torch.topk(logits, k).values[:, -1, None]
            logits = logits.masked_fill(logits < cutoff, float("-inf"))
            next_token = torch.multinomial(logits.softmax(-1), 1)
            token_ids = torch.cat((token_ids, next_token), dim=1)
        return token_ids

model = MiniGPT(vocab=vocab_size).to(device)
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)

for token_ids, targets in train_loader:
    optimizer.zero_grad(set_to_none=True)
    _, loss = model(token_ids.to(device), targets.to(device))
    loss.backward()
    optimizer.step()

                train.py · one optimizer iteration

                Microbatches become one mathematically scaled update

                1. Schedule: set the warmup/cosine learning rate on every optimizer group.
                2. Forward: run token windows under autocast and compute mean cross-entropy.
                3. Normalize: divide the loss by accumulation steps before backward.
                4. Accumulate: add gradients across microbatches; prefetch the next batch.
                5. Synchronize: in DDP, all-reduce only on the final microstep.
                6. Stabilize: unscale fp16 gradients, then clip their global norm.
                7. Update: AdamW changes parameters; GradScaler adjusts its scale.
                8. Release: set gradients to None and continue.

                Batch arithmetic

                \[\text{tokens/update}=B\times T\times A\times W\]

                B microbatch rows, T context tokens, A accumulation steps per rank, and W distributed ranks. The GPT-2 config uses (12×1024×5×8=491{,}520) tokens per optimizer update.

                Increasing accumulation preserves activation memory per microbatch, but changes update frequency, data order, communication, and sometimes optimization behavior.

                Data movement

                Memmap → pinned CPU → asynchronous GPU copy

                Random offsets slice contiguous next-token windows. Casting to int64 satisfies embedding lookup. Pinned host memory plus non_blocking=True allows copy/compute overlap when the hardware path supports it.

                Numerics

                TF32, bf16/fp16, and loss scaling solve different problems

                TF32 accelerates eligible float32 matrix multiplications on supported NVIDIA hardware. Autocast chooses operation dtypes. GradScaler protects fp16's small gradients; it is a no-op when disabled.

                Evaluation

                Validation is a repeated estimate, not one batch

                estimate_loss switches to eval mode, averages many random batches under no-grad, records train and validation separately, then restores training mode.

                Checkpoint

                Weights alone cannot reproduce training

                A resumable checkpoint includes model and optimizer state, architecture arguments, iteration, best validation loss, and run config. Reproducibility also needs data/tokenizer identity, code revision, environment, and random states.

                Compilation

                Compile around a stable repeated region

                nanoGPT compiles the model before DDP wrapping. Modern torch.compile may specialize and recompile under guard changes; static shapes and stable control flow improve reuse.

                Distributed training

                DDP replicates parameters and averages gradients

                Each rank owns a full model and optimizer. Different data creates different local gradients; all-reduce makes every replica apply the same update. This is data parallelism, not model-state sharding.

                sample.py + GPT.generate

                Training predicts every position; inference needs only the newest one

                With targets present, nanoGPT projects all hidden positions to [B,T,V] because every position contributes to the loss. Without targets, it applies the language head only to x[:,[-1],:], preserving a length-one time dimension and avoiding unnecessary vocabulary projection at earlier positions.

                1. Crop the growing prompt to the last block_size tokens.
                2. Recompute the model over that full cropped context.
                3. Select the final-position logits and divide by temperature.
                4. Keep only top-k candidates by setting other logits to negative infinity.
                5. Softmax, sample with multinomial, append, and repeat.

                The KV-cache boundary

                nanoGPT does not cache keys and values. At every new token it recomputes attention projections and block activations for the cropped prefix. That keeps the educational code tiny but repeats work.

                A cached decoder stores each layer's past K/V tensors and computes only the new query/key/value. Compute falls substantially during token-by-token decoding, while cache memory grows roughly with 2 × L × B × T × C × bytes.
